Data analytics project · Databricks

Where do New York's bikes disappear to every morning?

I built a pipeline that polls every Citi Bike station in NYC every 15 minutes, cleans the data through a bronze → silver → gold lakehouse, and maps which stations run out of bikes or docks, and when.

How it works

A scheduled Databricks job fetches live data, then a declarative pipeline loads it incrementally and refreshes every downstream table in dependency order.

Source

GBFS API

Citi Bike's public station status and station info feeds.

Bronze

Raw snapshots

Auto Loader appends new JSON files as-is, with file lineage.

Silver

Clean rows

One row per station per snapshot, typed and validated by expectations.

Gold

Metrics

Hourly empty/full rates and a commute-pattern profile per station.

The bug that made the charts honest

The first heatmap looked wrong. Tracking down why became the most useful part of the project.

The symptom

79

stations appeared empty 100% of the time, crowding every "worst stations" ranking with a flat, meaningless block of color.

The causes

  • Operating flags arrived as 1/0 but were parsed as booleans, silently becoming NULL. Closed stations looked identical to drained ones.
  • Some stations had zero capacity, making them "empty" by definition.

The fix

  • Parsed the flags as integers and derived booleans explicitly
  • Rebuilt silver from bronze, with no data re-fetched
  • Counted empty time only while a station is operating
  • Labeled dead stations as Out of service

The safeguard

A new pipeline expectation flags any unparsed operating status, so this failure now shows up in the pipeline UI instead of hiding in the numbers.
